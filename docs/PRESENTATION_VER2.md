# Mini Redis · 4분 발표 대본 Ver2

## 0:00–0:25 · 비교 기준과 순서

> README 첫 표에서 동시성과 무효화를 차례로 짚는다.

저희 조는 AI로 각각 Mini Redis를 만든 뒤 두 코드를 비교했습니다. 첫째는 **동시성**, 여러 요청이 겹칠 때 저장소를 어떻게 보호하는지입니다. 둘째는 **무효화**, 원본이 바뀌었을 때 예전 캐시를 어떻게 처리하는지입니다. 먼저 두 서버의 구조를 살펴보고, 각 방식을 쓰면 어떤 장점과 비용이 있는지 비교한 뒤, 마지막으로 왜 현재 코드를 선택했는지 설명드리겠습니다.

## 0:25–1:35 · 동시성

> [동시성](../README_VER2.md#concurrency) 표에서 현재 코드의 연결별 스레드와 비교 코드의 단일 이벤트 루프를 차례로 짚는다.

먼저 동시성입니다. 한 요청이 끝나기 전에 다른 요청이 들어와도 두 코드 모두 저장소 연산은 하나씩 처리합니다. 그래서 오래 걸리는 연산 뒤에 짧은 조회가 밀릴 수 있다는 점은 같습니다. 차이는 그동안 다른 연결을 누가 맡느냐에 있습니다.

현재 코드는 연결마다 담당 스레드가 있습니다. A가 저장소를 쓰는 동안에도 B의 스레드는 요청을 받아 읽을 수 있습니다. B도 저장소를 쓸 차례가 되면 그때 공통 락을 기다립니다. 이렇게 연결을 따로 맡기는 대가로, 아무 요청도 보내지 않는 연결에도 스레드가 하나 필요합니다.

비교 코드는 한 스레드가 준비된 연결을 골라서 요청을 읽고 명령까지 실행합니다. 연결이 늘어도 담당 스레드를 더 만들 필요가 없습니다. 대신 A의 명령이 오래 걸리면 B의 요청이 이미 도착해 있어도 서버가 그 요청을 읽는 일부터 늦어집니다.

## 1:35–3:20 · 무효화

> [무효화](../README_VER2.md#invalidation)의 첫 표에서 요청과 비용을 비교한다. ‘삭제 시도 직후의 첫 조회’ 표에서는 찾는 키 → 삭제 성공 → 삭제 실패 순서로 짚는다.

서버 안에서 요청을 처리하는 방식에 이어, 이번에는 API에서 조회와 삭제가 겹치는 상황을 보겠습니다. 원본 가격이 바뀌면 캐시에 남은 예전 가격을 다시 쓰지 않아야 합니다. 이게 무효화입니다. 비교 코드는 호출자가 캐시를 지울 시점을 정하고, 현재 코드는 상품을 수정할 때 API가 무효화를 함께 처리합니다.

비교 코드는 원하는 사용자의 캐시만 골라 지울 수 있습니다. 이미 사용자 정보를 읽고 있는 요청이 있더라도 삭제 요청은 먼저 끝날 수 있습니다. 대신 그 조회가 나중에 같은 키를 다시 채울 수도 있습니다. 현재 코드는 같은 상품을 조회해서 캐시에 채우는 동안 수정 요청이 기다립니다. 수정할 차례가 되면 가격과 캐시 키의 버전을 함께 바꾸고, 이전 키를 지웁니다.

아래 표는 중간에 다른 요청이 끼어들지 않았을 때의 첫 조회입니다. 삭제에 성공했다면 두 코드 모두 캐시가 비어서 원본을 다시 읽습니다. 차이는 표의 마지막 줄, 삭제에 실패해서 예전 값이 그대로 남았을 때 드러납니다.

왼쪽에서 상품 가격을 1,000원에서 1,200원으로 바꾸면 다음 조회는 버전 2를 찾습니다. 1,000원이 버전 1에 남아 있어도 버전 2는 비어 있으니 원본에서 1,200원을 읽습니다. 오른쪽의 비교 코드는 사용자 캐시를 지우기 전에도, 지운 뒤에도 같은 키를 찾습니다. 그래서 삭제에 실패해 그 키에 만료되지 않은 값이 남아 있다면, 원본을 다시 읽지 않고 그 값을 돌려줄 수 있습니다.

## 3:20–4:00 · 현재 코드를 선택한 이유

> [선택 이유](../README_VER2.md#selection)의 첫 행에서 두 서버의 비용을 짚고, 둘째 행에서 가격을 수정한 뒤의 동작으로 마무리한다.

동시성만 보면 현재 코드는 연결마다 스레드가 필요하고, 비교 코드는 긴 명령 하나가 끝날 때까지 다른 연결의 요청도 밀릴 수 있습니다. 이 차이만으로 어느 한쪽을 고르기는 어려웠습니다.

선택을 가른 건 무효화였습니다. 현재 코드는 같은 상품의 조회와 수정이 겹치면 한쪽이 기다립니다. 그 비용을 감수한 이유는 가격을 바꾼 사람이 예전 캐시까지 제대로 지워졌는지 확인할 필요가 없기 때문입니다. **수정이 끝나면 다음 조회는 새 버전 키를 사용한다는 점**을 더 중요하게 봐서 현재 코드를 선택했습니다. 감사합니다.
