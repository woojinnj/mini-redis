# Mini Redis · 동시성과 캐시 무효화

Mini Redis는 여러 클라이언트가 키와 값을 읽고 쓰는 메모리 저장소입니다. 정글 가이드라인의 두 기준으로 현재 코드와 비교 코드의 설계 선택을 살펴봤습니다.

| 순서 | 비교 기준 |
|---|---|
| [1. 동시성](#concurrency) | 여러 요청이 같은 저장소를 쓸 때, 누가 어떤 작업을 기다리는가 |
| [2. 무효화](#invalidation) | 원본이 바뀐 뒤, 이전 캐시를 누가 어떻게 무효화하는가 |
| [3. 선택 이유](#selection) | 상품 수정 후 첫 조회에서 중요하게 본 동작 |

<a id="concurrency"></a>

## 1. 동시성 · 여러 요청이 공유 저장소를 쓰는 구조

여러 요청의 처리 시간이 겹치면 같은 값을 동시에 바꿀 수 있습니다. 두 코드 모두 한 명령의 읽기와 쓰기 사이에 다른 명령이 끼어들지 않도록 합니다.

| 설계 선택 | 얻는 점 | 감수하는 비용 |
|---|---|---|
| **현재 코드** · 연결별 스레드 + 저장소 락(`RLock`) | A가 입력을 기다리는 동안 B의 스레드는 자기 요청을 처리 | 연결마다 스레드가 필요. A가 **저장소 락을 잡고 있으면** B는 다른 키를 읽을 때도 대기 |
| **비교 코드** · 단일 이벤트 루프 | 한 스레드가 입력이 준비된 연결을 골라 처리. 연결별 스레드와 저장소 락이 필요 없음 | A의 명령이 오래 걸리면 **루프가 그 명령을 끝낼 때까지** B의 짧은 명령도 대기 |

**같은 키에 두 번 증가를 요청한 예** · 처음 값은 0

| 요청 방법 | 실행 순서의 예 | 최종값 |
|---|---|---|
| A와 B가 각각 `INCR` 한 번 | A가 0 → 1 저장, 이어서 B가 1 → 2 저장 | **2** |
| A와 B가 각각 `GET` → 계산 → `SET` | 둘 다 0을 읽은 뒤 각각 1을 저장 | **1이 될 수 있음** |

캐시를 읽고 다시 채우는 과정도 여러 명령에 걸칩니다.

<a id="invalidation"></a>

## 2. 무효화 · 다음 조회에서 예전 값을 쓰지 않는 방법

| 설계 선택 | 얻는 점 | 감수하는 비용 |
|---|---|---|
| **현재 코드** · `PUT /products/1`에서 가격과 캐시 버전을 함께 변경 | 호출자는 가격만 수정. 예전 키 삭제가 실패해도 다음 조회는 새 키를 사용 | 같은 상품의 캐시 조회가 원본 응답을 기다리는 동안 수정도 대기. 상품별 락은 API 한 프로세스 안에서만 공유 |
| **비교 코드** · `DELETE /users/1`로 특정 캐시를 직접 삭제 | 호출자가 대상과 시점을 정할 수 있고, 진행 중인 원본 조회가 끝나기 전에 삭제 요청을 마칠 수 있음 | 삭제 시점을 호출자가 챙겨야 함. 먼저 시작한 조회가 삭제 뒤 같은 키를 다시 채울 수 있음 |

**비교 코드 · 조회 A와 삭제 B가 겹치는 예**

| 순서 | 조회 A | 삭제 B |
|---|---|---|
| ① | `GET user:1` → 캐시가 비어 원본 조회 시작 | |
| ② | 원본 응답을 기다림 | `DEL user:1` 처리 완료 |
| ③ | 원본 응답을 받아 `SET user:1` | |

**현재 코드 · 상품 가격을 1,000원에서 1,200원으로 바꾸는 예**

- **상품별 락**으로 순서를 맞춥니다. 조회가 먼저 락을 잡으면 캐시 채우기가 끝난 뒤 수정합니다. 수정이 먼저 락을 잡으면 조회가 기다립니다.
- **버전 키**로 다음 조회 대상을 바꿉니다. 예전 키(`v1`)를 지우지 못해도 다음 조회는 새 키(`v2`)를 찾아 바뀐 가격으로 캐시를 채웁니다.

<a id="selection"></a>

## 3. 현재 코드를 선택한 이유

**동시 증가의 결과는 두 코드 모두 2입니다. 선택을 가른 건 가격 수정 직후의 첫 조회였습니다.**

| 선택 기준 | 팀의 판단 |
|---|---|
| 감수한 비용 | 같은 상품을 조회하고 수정하면 한쪽이 기다릴 수 있음 |
| 우선한 동작 | 가격 수정 요청 하나로 다음 조회가 새 가격을 읽음. 호출자가 이전 캐시를 지울 시점을 따로 맞출 필요가 없음 |
